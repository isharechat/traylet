# 系统权限说明

Traylet 仅在对应功能需要时请求 macOS 系统权限，所有授权均遵循 macOS 原生授权流程，不修改 TCC 记录、不绕过系统安全机制。

## 权限清单

在「设置 → 权限」中可集中查看并管理以下三项系统权限：

| 权限 | macOS 设置路径 | 必需性 | 用途 |
| --- | --- | --- | --- |
| **屏幕录制** | 隐私与安全性 → 屏幕录制 | 截图必需 | 用于区域截图、整屏截图与截图翻译 |
| **辅助功能** | 隐私与安全性 → 辅助功能（macOS 26 亦见「设备控制和数据访问」） | 可选 | 用于输入翻译快捷键读取其他应用的选中文本 |
| **登录时启动** | 通用 → 登录项与扩展 | 可选 | 控制是否在登录 macOS 后自动在菜单栏打开 Traylet |

> 说明：当使用辅助功能兜底策略通过 AppleScript 读取浏览器（如 Safari / Chrome / Edge）当前选中文本时，首次调用可能额外触发 macOS「自动化」控制提示。

## 状态查看与快速跳转

- **未允许**：权限行显示「请求权限」按钮（触发系统授权提示）以及「打开系统设置」快捷入口。
- **已允许**：显示绿色「已允许」状态徽标，并保留「打开系统设置」入口以便随时查看或撤销。
- 授权变更后返回 Traylet 窗口时，权限状态会自动刷新。

## 为什么更新或重编译后有时需要重新授权？

macOS 的 TCC 权限记录与应用的代码签名身份绑定：

- **本地源码构建 / `-preview` 预览包**：使用 ad-hoc 签名，每次重新编译或升级后签名哈希（`cdhash`）会发生变化，macOS 会将其视为新的二进制，导致旧权限失效。
- **Developer ID 签名正式版**：签名身份（Team ID + Bundle ID）在版本间保持一致，权限可跨升级保留。

当 Traylet 检测到「此前曾允许但当前已失效」的系统权限时，会在启动时弹出一次轻量级的「权限需要重新授权」引导弹窗，帮助你直接跳转到对应权限设置；全新首次安装的用户不会收到该弹窗。
